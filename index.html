Building robust data pipelines

Darren Hutton & Jonathan Abbott

Welcome everyone. Joint talk — frame the problem of pipelines that must scale across modes, not just one Azure service tour.

Azure building blocks

Services that help us scale

  • Communication Services
  • SignalR Service
  • Stream Analytics
  • Data Catalogue / Schema Registry
  • Functions (incl. Logic Apps)
  • Storage (Blob, Queues, Tables)
  • Application Insights
  • Data Factory
  • Service Bus

These help us scale, but…

Don’t dwell on each service. The beat is: tooling alone isn’t a pipeline strategy — modes and patterns matter more.

Data processing modes

You’ll likely need more than one — sooner than you think.

Walk through three common modes. Punchline lands on the last slide.

Smaller / medium, semi-conformed

  • Often notebooks and experiments
  • Security and permissions dominate
  • Data is partially shaped, not fully curated

Large datasets, scheduled processing

  • Batch windows and orchestration
  • Interruptions and restarts matter
  • Watch impact on transactional systems

Time-series / event data

  • Streaming and near-real-time paths
  • Hard to conform reference data
  • Expect eventual consistency

The reality check

You’ll likely need to support more than one mode within ~3 months.

Design for mixed modes early — don’t assume a single pattern will hold.

What’s generating the data?

  • Front-end client / WebRTC
  • Azure Communication Services — network traversal
  • SignalR — real-time push to clients and services
Start at the source: interactive clients and real-time channels feed the pipeline before anything lands in storage.

Landing zone

  • Security gateway — often a public share
  • API gateway
  • Azure data shares
  • Virus checking
  • Flagging & quarantine — human review before trust
Ingress is a control point: validate and quarantine before raw data becomes “in the estate.”

Medallion pattern

  • Increasing data quality through layers
  • Simple mental model
  • Replay / time-travel
  • ACID where it counts
  • Incremental ETL
  • Layers can be mixed-mode per dataset
Medallion is a quality ladder, not a rigid one-size architecture. Mix modes per dataset as needed.
Bronze

Raw, unvalidated

  • Incremental append
  • Streaming and batch both land here
  • Preserve source fidelity for replay
Silver

Validated, enriched, trusted

  • Schema checks and cleansing
  • Enrichment with reference data
  • Ready for downstream consumers
Gold

Curated for use

  • Aggregated for analytics, ML, and apps
  • Transforms turn data into knowledge
  • Aggregations done before write — low-latency reads

Democratising data

  • Reporting API — controlled access for consumers
  • HAL — Hypertext Application Language for discoverable hypermedia APIs
Make data reachable without handing out warehouse access: APIs with clear navigation (HAL) help teams self-serve safely.

Data as a product

  • Create, maintain, and validate datasets accessible by all
  • Mindset: curate data-as-products, not just tooling
  • Ownership, quality, and discoverability are first-class
Closing mindset slide: pipelines succeed when datasets are treated like products with owners and SLAs.
